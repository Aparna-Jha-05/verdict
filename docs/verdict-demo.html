The problem

The cheapest invoice to pay is not the safest one

Accounts-payable teams process thousands of invoices. The costly mistakes aren't typos — they're a changed bank account that quietly reroutes a real payment to a fraudster, a resubmitted invoice with one digit altered, or a total that doesn't add up and slips through because a tired human trusted the paperwork.

"An LLM reads a PDF" is a commodity — every team can do it. The value Verdict adds is everything that happens after the model believes the document: deterministic math, fraud forensics, and a human gate.

The differentiator

The model proposes. Deterministic rules decide.

One architectural rule, enforced in code

The vision model extracts and explains. It is never allowed to render a verdict. Validation and fraud detection are pure Python over the extracted facts — reproducible, auditable, and impossible to prompt-inject.

validate.py · fraud.py · dedup.py → never call an LLM

Vision-first no OCR

Every upload — PDF, scan, or photo — is normalized to a page image and read directly by a vision-language model. No brittle OCR templates that break on a skewed phone photo.

Confidence escalation routing

A cheap model runs by default. Low confidence, a parse failure, or an extraction-type error auto-escalates to a stronger model — pay for the hard cases only.

Deterministic fraud no LLM

PDF metadata forensics, vendor bank-detail changes, and semantic near-duplicate detection — the same "verify what the model believed" pattern as validation.

Visual grounding bbox

Every extracted field carries a bounding box. Hover a value and its source lights up on the invoice image — the system shows its work, on the document itself.

How it works

One pipeline, one hard boundary

A single normalization step makes "parse a photo" and "parse a clean PDF" the same code path. Everything to the right of extraction is deterministic.

Anticipate the room

Questions a mentor will ask

Isn't this just an LLM reading a PDF?

No — that's the commodity part. The differentiator is the two deterministic layers and the human gate wrapped around the model. The model never renders a verdict; it proposes facts, and reproducible Python decides. That separation is the product.

What if the model extracts something wrong?

Two safety nets. First, low confidence auto-escalates to a stronger model. Second, validation is deterministic math over the extracted numbers — a wrong total or a bad line item fails regardless of how confident the model was. And the human edits any field before approving.

How is the fraud detection not just more AI?

It's pure Python. Bank changes compare against the SQLite ledger of prior approvals. Duplicates use exact-match plus local embeddings. PDF forensics reads the metadata dictionary. Every flag is reproducible from stored facts — no model call, so nothing to hallucinate or prompt-inject.

Why "flag for review" instead of "fraudulent"?

Deliberate. The system never claims a document is authentic or fraudulent — it surfaces evidence and keeps the decision with a human. Over-claiming authenticity is how automated systems create liability. Verdict flags; people decide.

Does it scale / cost?

The cheap model handles the common case; only low-confidence documents pay for the stronger one — "intelligent inference layering." Embeddings run locally with no API dependency. The whole thing deploys on free tiers today.

What's next?

Three-way match against purchase orders and goods receipts (already scaffolded), then multi-page and multi-currency hardening. The deterministic-layer pattern extends cleanly to each new check.
